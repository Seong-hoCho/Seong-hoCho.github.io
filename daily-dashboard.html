      어떻게 쓰나요?

      다시 읽는 칸이 아니라 다시 떠올리는 칸입니다. 노트를 눈으로 훑으면 아는 것 같지만, 시험장에서는 백지에서 꺼내야 합니다. 그래서 내용이 아니라 질문을 적습니다.

      1. 공부를 마치면 그날 배운 것에서 질문을 2~3개 뽑아 적습니다. 답도 함께 적어두면 채점이 됩니다.
      2. 다음 날 목록에 뜨면 답을 보기 전에 먼저 소리 내어 답해 봅니다.
      3. 답 보기로 확인한 뒤 맞았으면 기억함, 막혔으면 다시를 누릅니다.
      4. 기억함을 누를 때마다 다음 복습이 1 → 3 → 7 → 16 → 35일 뒤로 멀어집니다. 막힌 것만 자주 돌아옵니다.

      좋은 질문 — 정의, 조건, 공식의 유도 이유, 두 개념의 차이.
      “베이즈 정리에서 Posterior는 무엇에 비례하는가?” / “Jeffreys prior가 불변인 이유는?”

      피할 질문 — 계산 문제 전체, “5장 복습”처럼 범위만 적은 것. 30초 안에 답할 수 있는 크기로 쪼개는 편이 오래갑니다.

      구글 캘린더 간편 연동 연결 안 됨

      설정에서 연동을 마치면 앞으로 7일간의 일정이 표시되고, 위 달력에도 함께 나타납니다.
      연동 설정 방법

      방법 A · 간편 연동 (Apps Script · 권장)
      구글 클라우드 콘솔이 필요 없습니다. 함께 받은 google-calendar-bridge.txt 파일을 사용합니다.

      1. script.google.com에 접속해 새 프로젝트를 만듭니다.
      2. 기본 코드를 모두 지우고 브리지 코드를 붙여넣습니다.
      3. 맨 윗줄 TOKEN 값을 본인만 아는 문자열로 바꾸고 저장합니다.
      4. 함수 목록에서 setup을 골라 실행하고 권한을 승인합니다.
      5. 배포 → 새 배포 → 웹 앱, 실행: 나 / 액세스 권한: 모든 사용자로 배포합니다.
      6. 발급된 /exec URL과 토큰을 이 대시보드 설정에 입력합니다.

      참고 — 이 웹 앱은 캘린더뿐 아니라 대시보드 데이터 전체를 저장해 다른 기기와 동기화하는 데도 함께 쓰입니다(구글 드라이브에 파일 하나로 저장됩니다). 브리지 코드를 새 버전으로 바꿨다면 setup을 한 번 더 실행해 드라이브 접근 권한을 승인한 뒤 배포 → 배포 관리 → 새 버전으로 배포까지 마쳐야 반영됩니다.

      방법 B · 직접 연동 (OAuth)
      Google Cloud Console에서 Calendar API를 켜고 OAuth 클라이언트 ID를 발급받아 설정에 입력합니다. 이 페이지는 https:// 주소에 올려야 하며, 그 주소를 승인된 자바스크립트 원본에 등록해야 합니다.
